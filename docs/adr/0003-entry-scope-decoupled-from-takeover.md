# 入口按路径出现，接管在激活时校验

“帖子”入口的出现条件与接管校验曾经绑定在同一次 `inspectHost` 全量检查上：正文结构或 evidence 锚点不满足的页面连入口都不插入。这在真实环境中把问题**隐藏**了——入口静默消失，用户与开发者都无法区分“范围外”与“校验失败”（实测：登录态 friends 页因兄弟组件 `bangumi-friend-sorter` 在 `.mainWrapper` 内插入排序条而入口消失）。本项目改为**入口与接管解耦**：

- 入口插入只依赖页面范围（路径一级段 allowlist + 任意深度，排除 doujin 与未知段）与原生日志链接身份校验；
- 接管所需的全量安全检查（正文 columns/footer 结构、shape 与 evidence 锚点、二级导航规则）推迟到激活时（入口点击或 `#posts` 深链）执行；
- 激活时校验失败不隐藏任何宿主节点，在二级导航位置插入带身份标记的错误面板“无法安全挂载帖子视图”，并输出控制台诊断；重复点击入口重试校验。

这是一个取舍：fail-visible 换掉入口层面的 fail-closed。接管本身仍是 fail-closed 的——校验不通过绝不隐藏宿主内容。选择解耦而非放宽接管校验，是因为误接管的代价（藏起用户内容且恢复无保障）不可降低，而入口静默消失的代价（问题被掩盖）可以用可见错误消除。

## Considered Options

- 维持入口与校验绑定，仅修正过严实现：被拒——校验失败依旧表现为“入口消失”，与范围外不可区分，掩盖真实共存问题。
- 放宽接管校验（弱锚点页面直接接管）：被拒——误接管风险不可接受，与 `spec/host-view.md` 的恢复义务冲突。

## Consequences

- 范围内的未知或结构漂移页面会出现“点了报错”的入口；这是有意暴露问题，不是缺陷。
- 错误面板是本组件唯一在未接管状态下插入宿主的节点；不隐藏任何宿主内容。
- wiki 族页面（`/user/{key}/wiki/**`）无内容 evidence 锚点，仅靠路径 + 列结构校验，是显式记录的最弱校验页型。
- 兄弟组件在 `.mainWrapper` 内、`.columns` 之外的节点（如排序条）在接管期间保持可见；本组件以语义选择器定位 `.columns`，不依赖子节点序号。
