# 缓存优先与头批核验

SearchEncore 无快照保证，完整重扫既不能证明历史一致性，也会放大请求。项目选择按用户保存已成功完成有限目标的来源前缀，用每条流一次头批核验换取快速进入与更少请求；接受头部之外的变化可能无法发现。头部变化后重新建立有限前缀而非拼接旧尾部，避免把漂移的 offset 当作同一份数据。

来源缓存独立提交，但全部帖子的可见列表在两条流都结束后统一发布，避免同一轮更新连续跳动。完整目标提交而非逐批持久化，确保失败或关闭后的半成品不成为下次免请求的依据；目标期间的内存展示与持久化完成是不同保证。行为规则唯一维护于 [`spec/feed.md`](../spec/feed.md)。
