# 数据流与调度

## 数据源与请求边界

- 所有 SearchEncore（bgmdb.ry.mk）请求集中在独立 adapter；renderer、route 和 DOM 模块不得自行发请求。请求用普通 `fetch` 且 `credentials=omit`，不使用 GM 特权请求。
- 仅在进入有效且可安全挂载的帖子视图后查询；切分类或退出不以取消为默认，见下文调度。
- 契约细节见 [`external/search-encore.md`](../external/search-encore.md)；本文记录的是使用该契约的项目侧约束。

## 归一化与 envelope 校验

- 两个搜索 endpoint 的结果 normalize 为共同的领域模型；endpoint / normalizer 负责标记 `group` 或 `subject`，view 不依赖 API 的数字 kind 推导 URL。
- 主题身份是 `(kind, id)` 组合，不能只按 id 去重。参与身份和 URL 的 ID 必须可作为有效安全整数处理；不猜 ID、不以精度丢失的整数构造链接。
- envelope 含 `data`、`pagination`、`meta`。`meta` 必须是对象且含非负整数 `executionMs`，允许额外字段；损坏的 envelope 使整批失败，不能把 `data: []` 当成可靠空结果。
- 关键字段损坏整批失败，保留已有缓存并允许重试；不部分接收坏批次。合法可省略字段（parentName、creatorID、creatorName）缺省或为 null 时正常降级。
- 源数据中的标题、昵称、来源等按文本呈现，不作为 HTML/脚本插入；URL 只用经过验证的安全整数 ID 与允许域名构造。

## 排序与缓存

- 三类视图均按创建时间降序。相同创建时间：同一来源保留 API 首次接收顺序，跨来源固定小组话题在前。不额外扫描并列时间边界，不承诺刷新后并列顺序一致。
- 缓存仅存续于当前文档生命周期：内存共享、不自动刷新、不轮询、无独立刷新按钮、不持久化；整页刷新后重新获取。
- 同一身份首次成功接收的数据在本次文档内保留，不后台修改旧页的标题、回复数或排序。

## 冻结页与晚到排除

- 各分类保存已展示页的帖子身份序列（不每次对整个缓存排序后切片）、最近访问页码和晚到排除集合；三分类共享规范化数据。
- 后续发现本应排入某分类已展示区间的主题（晚到主题）时，仅在该分类本次浏览中排除；不从共享缓存删除，也不妨碍其他未冻结分类使用。冻结比较采用完整排序规则，不只比较时间戳。
- 接受动态索引下的遗漏，不承诺完整快照；不为 offset 漂移做后台重扫（见 ADR 0002）。

## 合并与有效前缀

- “全部帖子”合并两条流；不得将同一 offset 同时套到两个 endpoint 后直接拼接。
- 为保证合并前 N 条正确，每条流需有至少 N 条有效前缀或已自然读尽。原始返回行数、唯一缓存数量、某分类合格候选数是不同计数；去重或排除的条目不能充当有效前缀。

## 分页与一条前瞻

- 每页 10 条；已确认存在的页可按数字直接跳转，不显示估算总页数。各分类仅在可见页成功发布时记住已展示页及其前瞻确认的下一页，确认记录在本次文档内单调保留；后台结果不直接扩展可见页码。
- 一条前瞻：目标所需前缀再加 1 个候选（如单分类第 1 页取 11 条，显示 10 条，第 11 条留缓存用于确认下一页）。按目标缺口请求，不为凑满 limit 预取整页。前瞻不作为已展示条目冻结，不提前提交下一页为当前页，但可确认其存在并显示数字链接。
- 下一页三态分开：已确认有、已自然读尽、未知（失败/预算/服务上限等各自标记）。前瞻成功只证明至少存在一个后续候选，不保证下一页有 10 条或请求必成。
- 仅在目标页可靠准备完成后提交页码；失败保留旧页及其页码。目标页已可靠确定时，仅前瞻失败或预算不足不阻止展示当前页，下一页保持未知并提供显式继续/重试。
- 自然读尽后不足 10 条的尾页正常展示；显式继续确认没有后续后保留当前页并关闭下一页入口，不跳到空白页。

## 游标与终止

- 使用通过校验的原始服务分页进度推进游标；核对响应 offset/limit 与请求一致，异常回显不能静默当正常数据。不按去重后新增条数推进 offset。
- 客户端不派发 offset > 5000（服务钳制上限，非数据总量）；到达检索上限仍可展示已充分确定的缓存页，但不能冒充自然读尽。
- 终止状态需区分：自然读尽、服务检索上限、有效候选不足但游标前进、协议无进展、网络失败、请求预算耗尽。零条有效新增不等于空结果，短批次、重复整批和读尽不是同一状态；缺少依据时不得仅凭短批次或零新增断言结束。估算 `total` 不作为终止依据。

## 调度与预算

- 应用层全局最多 2 个在途请求，每条流最多 1 个。当前分类所需的双流均为前台；前台仍有待办或在途时不派发纯后台请求，在途的后台请求不取消，其成功结果仍可入缓存。
- 切分类或退出后，旧任务只完成已触发的页目标及一条前瞻，不预取完整后续页、不抓全部历史；重入复用任务与缓存。整页跳转或关闭后不保证继续，不持久化待办。
- 每次用户加载目标，每条流最多 3 次请求（含初次与共享在途）；需求合并不得绕过预算，切分类或重入不重置同一目标预算。预算耗尽且目标页未可靠确定时保留旧页，等待显式继续。
- 单请求 15 秒超时。普通失败停止该目标后续派发，不自动重试；重试绑定失败目标并复用成功缓存，其他在途成功与独立可用分类不受影响。
- HTTP 429 全局暂停新请求：有可读有效 `Retry-After` 时遵守，否则冷却 60 秒；多个 429 不缩短既有期限；冷却结束不自动恢复，须显式重试。全局暂停与目标失败独立保存；切分类、重入、成功回调不能解除暂停或隐式重试；已有充分缓存的视图不因暂停被遮蔽。

## 归属与发布

- 请求任务按启动时捕获的用户 key、endpoint、offset/limit 绑定归属；回调不得读取可能已变化的当前用户。
- 发布 UI 前核对当前路由与意图；后台完成不提交可见页码、不冻结尚未展示的页面、不抢回视图/焦点/滚动，不向宿主页弹提示——回到相关分类后再显示错误与重试。

## 失败语义

- 一条流失败时不把另一流冒充完整的“全部帖子”结果：保留已成功显示的旧页，没有旧页则显示错误与重试；允许切到可用单分类，重试复用已成功取得的数据。
