# 数据流与调度

## 数据源与请求边界

- 所有 SearchEncore（bgmdb.ry.mk）请求集中在独立 adapter；renderer、route 和 DOM 模块不得自行发请求。请求用普通 `fetch` 且 `credentials=omit`，不使用 GM 特权请求。
- 仅在进入有效且可安全挂载的帖子视图后查询；切分类或退出不以取消为默认，见下文调度。
- 契约细节见 [`external/search-encore.md`](../external/search-encore.md)；本文记录的是使用该契约的项目侧约束。

## 归一化与 envelope 校验

- 两个主题搜索 endpoint 的结果归一化为共同的主题模型；endpoint / normalizer 标记 `group` 或 `subject`，view 不依赖 API 的数字 kind 推导 URL。评论回复使用独立模型与 `source=all` 单流，不把六来源拆为六条流，也不借用主题来源标记。
- 主题身份是 `(kind, id)`，评论回复身份是独立命名空间的 `(source, id)`；不能只按 id 或所在对象 ID 去重。未知回复来源整批失败，不猜路径或静默筛掉。参与身份和 URL 的 ID 必须可作为有效安全整数处理；不猜 ID、不以精度丢失的整数构造链接。
- envelope 含 `data`、`pagination`、`meta`。`meta` 必须是对象且含非负整数 `executionMs`，允许额外字段；损坏的 envelope 使整批失败，不能把 `data: []` 当成可靠空结果。
- 关键字段损坏整批失败，保留已有缓存并允许重试；不部分接收坏批次。合法可省略字段（parentName、creatorID、creatorName）缺省或为 null 时正常降级。
- 源数据中的标题、昵称、来源等按文本呈现，不作为 HTML/脚本插入；URL 只用经过验证的安全整数 ID 与允许域名构造。

## 排序与缓存

- 四类视图均按创建时间降序。主题相同创建时间：同一来源保留 API 首次接收顺序，跨来源固定小组话题在前；评论回复相同创建时间保持统一回复流的首次接收顺序，不按六来源重排。不额外扫描并列时间边界，不承诺刷新后并列顺序一致。
- 缓存仅存续于当前文档生命周期：内存共享、不自动刷新、不轮询、无独立刷新按钮、不持久化；整页刷新后重新获取。
- 同一身份首次成功接收的数据在本次文档内保留，不后台修改旧页的标题、摘要、回复数或排序。

## 冻结页与晚到排除

- 各分类保存已展示页的内容身份序列（不每次对整个缓存排序后切片）、最近访问页码和晚到排除集合；三个主题分类共享规范化主题数据，回复集合与主题集合隔离。预加载页不提前冻结；跳到高页时，早已在缓存中的未访问低页内容不属于晚到内容。
- 后续发现本应排入某分类已展示区间的内容（晚到内容）时，仅在该分类本次浏览中排除；不从共享缓存删除，也不妨碍其他未冻结分类使用。冻结比较采用完整排序规则，不只比较时间戳。
- 接受动态索引下的遗漏，不承诺完整快照；不为 offset 漂移做后台重扫（见 ADR 0002）。

## 合并与有效前缀

- “全部帖子”合并两条流；不得将同一 offset 同时套到两个 endpoint 后直接拼接。
- 为保证合并前 N 条正确，每条流需有至少 N 条有效前缀或已自然读尽。原始返回行数、唯一缓存数量、某分类合格候选数是不同计数；去重或排除的条目不能充当有效前缀。

## 分段预加载与页发布

- 每页 10 条。四分类统一使用累计有效前缀目标：首次进入加载到 101 条；点击第 4–13 页提升到 201 条，第 14–23 页提升到 301 条，后续每十页增加 100 条。目标按分类只增不减，返回低页、切分类或重入不降低目标、不重复抓成功数据。
- 目标包含每百条之后的一条探测候选；不是 HTTP limit、原始返回行数或本次新增量。按有效缺口分批请求，不超过 adapter 的单批上限；全部帖子仍遵守每来源充分性或自然读尽的合并约束。
- 当前页可靠就先发布，余下继续有限预加载；不等待整个批次结束，也不因预加载禁止浏览已确认页。只有目标页尚未可靠准备好时禁止重复翻页；切分类和退出仍可用。
- 每批结果可扩大当前可见分类的可靠确认范围，确认记录在本次文档内单调保留。只确认可靠前缀证明至少有一项内容的页，不使用估算总数；确认不等于完整页已加载或已冻结。后台分类完成不更新可见页码，重返后再核对并发布；页码窗口规则见 [`ui.md`](ui.md)。
- 下一页三态分开：已确认有、已自然读尽、未知（失败/空转暂停/服务上限等各自标记）。当前页可靠时，批次未达目标或失败只作为预加载警告，不遮蔽列表；所需目标页不可靠则保留旧页及其页码，提供继续/重试。
- 自然读尽后不足 10 条的尾页正常展示；显式继续确认没有后续后保留当前页并关闭下一页入口，不跳到空白页。

## 游标与终止

- 使用通过校验的原始服务分页进度推进游标；核对响应 offset/limit 与请求一致，异常回显不能静默当正常数据。不按去重后新增条数推进 offset。
- 客户端不派发 offset > 5000（服务钳制上限，非数据总量）；到达检索上限仍可展示已充分确定的缓存页，但不能冒充自然读尽。
- 终止状态需区分：自然读尽、服务检索上限、有效候选不足但游标前进、协议无进展、请求重试耗尽、空转暂停。合法空批次才标记该来源自然读尽；零条有效新增不等于空结果，短批次、重复整批和读尽不是同一状态。估算 `total` 不作为终止依据。

## 调度与重试

- 应用层全局最多 3 个在途请求，每条流最多 1 个；三条查询流共享同一调度及429暂停，不能为回复另建独立请求池。当前分类相关的排队请求优先；没有可派发前台请求时允许后台使用空槽。在途后台请求不取消，其成功结果仍可入缓存。
- 切分类或退出后继续已触发的有限累计目标，不自动触发下一批、不抓全部历史；重入复用任务与缓存。整页跳转或关闭后不保证继续，不持久化待办。
- 成功抓取批数不设目标级上限。每个具体请求（绑定用户、endpoint、offset/limit）最多 3 次尝试：网络异常、15 秒超时、HTTP 408 和 5xx 可自动重试两次，分别等待 1 秒、2 秒再按当前优先级排队。等待不占并发槽，同来源不能越过它派发下一批；共享请求共用尝试次数，不能按等待分类重复重试。其他 4xx、响应校验失败不自动重试。
- 重试耗尽或不可重试错误停止该分类扩容；成功缓存保留，其他在途成功与独立可用分类不受影响。显式继续/重试或触发更高累计目标可从失败游标恢复并补齐前缀，不重抓成功数据；同一目标内浏览缓存页、切分类或重入不隐式重试。
- 某来源连续 3 个非空成功批次没有本分类有效新增时暂停该分类扩容，提供显式继续；有有效新增即清除该来源连续计数。计数包含去重和晚到排除之后的有效内容，不把暂停、重复数据或零新增冒充读尽。
- HTTP 429 全局暂停新请求：有可读有效 `Retry-After` 时遵守，否则冷却 60 秒；多个 429 不缩短既有期限；冷却结束不自动恢复，须显式重试。全局暂停与目标失败独立保存；切分类、重入、成功回调和更高目标不能解除暂停；已有充分缓存的视图不因暂停被遮蔽。

## 归属与发布

- 请求任务按启动时捕获的用户 key、endpoint、offset/limit 绑定归属；回调不得读取可能已变化的当前用户。
- 发布 UI 前核对当前路由与意图；后台完成不提交可见页码、不冻结尚未展示的页面、不抢回视图/焦点/滚动，不向宿主页弹提示——回到相关分类后再显示错误与重试。

## 失败语义

- 普通回复查询失败不影响独立可用的主题分类，反之亦然；已有成功缓存保留。全局429暂停规则仍覆盖三条流。
- 一条主题流失败时不把另一流冒充完整的“全部帖子”结果：保留已成功显示的旧页，没有旧页则显示错误与重试；允许切到可用单分类，重试复用已成功取得的数据。
